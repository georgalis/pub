ff plan

ff: functional find. A short-switch find with NetBSD find(1) semantics where they matter, one interface on Linux, Darwin and NetBSD, delivered as C99 source (ff.c) and a bash function (ff.fn.bash).

This plan drives the package revisions. It took this shape at r0.7, when the package took the shape of cksh's and srt's: before that the plan was PLAN.md, a design record by revision (r1 to r10 there), kept whole as section 14. Items marked V (section 2) began as ambiguities with a proposed default; nothing downstream of an unconfirmed V item was built until it was ruled on. Decisions are recorded in section 12, the affected sections state the decision in place, and section 13 holds the status of each revision as built. Where a decision reverses an earlier one, both are stated.

1 Purpose and scope

ff walks file trees and evaluates an expression for every node, as find does, with one letter per switch. It prints the names for which the expression holds, or with -v one cksh line per node, and with -k sorts what it prints by the columns of that line.

In scope: the walk, with an owned walker that never re-resolves a path it has checked; the primaries and actions of section 14; -v, the cksh line without a hash; sorting by column with the key grammar of srt and cksh; NUL-terminated records; a bash function that translates the same grammar to the native find and writes the same bytes.

Out of scope, by requirement: hashing (that is cksh, which reads the names ff prints); duplicate detection (that is srt -D); a global reverse option (V01); locale collation; -ok, -fprint, -printf, -flags, -fstype.

ff is one of three tools that share a record and a key grammar: ff finds files, cksh lists them, srt sorts listings. Section 4 holds the grammar the three agreed.

2 Intent verification

Each item states the ambiguity, the readings, and the ruling. V01 to V09 were ruled on 20261114, before r0.7 was built. V10 was not ruled on; it is built as proposed and stays open.

V01 Global reverse. The grammar model gives -r for all columns. In ff -r is the ERE primary and takes an argument. Readings: (a) no reverse-all in ff, only -kNr; (b) an uppercase option -R (srt's -R randomizes); (c) move the regex primary to another letter. DECIDED: (a). Full descent is written out, -k5r,4r,6r,1r,2r.

V02 -k list as the next word. r0.6 read only a joined value, so in ff -k 5 the 5 was a path. DECIDED: the cksh rule. The next word is the list when it reads as one (a column number first, in the widest sense srt gives a list, so a list ff refuses is reported as a list and not walked as a path). ff -k 5 sorts . by mdate; a directory named 5 is written ./5; -k 7 is a usage error. -k may also end a group of options, -Sk5. As built, one departure from cksh: a word that begins with - is never the list, since -0 and -1 are primaries in ff, so in -k -1 the -1 is false; joined, -k-1 is refused with the cksh wording.

V03 Repeated -k. r0.6: the last one wins. DECIDED: the cksh rule. -k5 -k4 is -k5,4; naming a column twice is an error.

V04 Column 3 and letters. r0.6: -k3 kept walk order and held nothing. DECIDED: the null column is a no-op sort, so -k3 orders by 1,2,4,5,6. Letters, as ruled: on columns 1, 2, 4 and 5 x is valid and means what the column already is, a number; columns 3 and 6 are text; r reverses a column of either type; -k-1 is refused. As built, following cksh on the two cases the ruling leaves unstated: x on column 3 or 6 is refused (tag 6ab7ff51), since x asks for a number where the column is text, and any letter other than r and x is refused (6ab7ff52), since the types are fixed. Letters combine in either order, -k5xr and -k5rx.

V05 Columns without -v. A default print writes the name alone. DECIDED: -kN sorts by columns that are not shown, as ls -t sorts without -l. Column numbers always name the -v layout and every record is keyed by its node's stat. The srt equivalence of section 4 item 5 holds for -v output.

V06 -Z with -v. r0.6: -Z ended only -f and default-print names; -v lines kept the newline. DECIDED: -Z, --zero-terminated, ends every record with NUL, with -f or not; srt's -Z is NUL-terminated records in and out. As built, names are written raw under -Z, to a terminal too, on -v lines as on names.

V07 Hash notation. ff computes no hash; column 3 is always a dot. DECIDED: documentation only. Column 3 is described as the place of cksh's shake256-N, shake256-6 by default, with no slash notation anywhere. No hashing is added to ff.

V08 -V. In cksh and srt -V is the version; in ff it shows the native find command. DECIDED: ff keeps -V and gains --version only. --man and the formatter-driven --help follow cksh.

V09 Function hand-over. DECIDED: the function runs a binary named ff on PATH, with --fn and --bin to allow only one form; -V implies --fn, since only the function has a native command to show. As built: an explicit --bin with -V reaches the binary, which notes -V and runs; --fn with --bin is a usage error (6ab7ff55); --bin with no binary is status 2 (6ab7ff56); the binary refuses --fn (6ab7ff54) and accepts --bin. The words that choose the form are options, so they are not seen where an option is not: as the argument of a primary, among the words of an -x or -j command, or after --.

V10 Revision naming. OPEN, built as proposed. The six dated revisions are named r0.1 to r0.6 and this one r0.7; the r1 to r10 labels of PLAN.md stay in section 14 as that record's own numbering. The alternative, r0.6 to match the cksh and srt archives, is a change of label in the headers, FF_REV, the manual REVISION and the test of --version.

3 Interface

ff [-IHLDSXZV] [-k [col[r][,col[r]]...]] [--] [path ...] [expression], ff -h | --help | --man | --version, ff --fn ... | ff --bin ....

Options are uppercase letters, and -k, global, accepted anywhere except as the argument of a primary. Primaries are lowercase letters, the digits 0 and 1, or -mode and -delete. The option and primary tables, with their rationale, are in section 14 (Grammar); --help is the statement of the current implementation.

4 Key grammar shared with srt and cksh

Settled first in srt (plan-srt.md, section 2), built in cksh (plan-cksh.md, section 4), and stated for ff as the model of this revision:

  1. Columns are words in the awk sense, counted from 1; widths and padding are not significant, and blanks may be squeezed.
  2. Sorting is asked for with -k list, col[opts][,col[opts]]...: the named columns in the order given, then the remaining columns left to right. Ties follow srt's order.
  3. A bare -k names no column. That means sort by file name; in srt, by whole record.
  4. Reverse is -kNr for one column or -r for all. -krN is not accepted.
  5. ff knows column types, so -k5,4,6 is srt -k5x,4x,6,1x,2x,3 on their output: node, links, time, and size by hexadecimal value, the hash and name as text.
  6. The name begins in column 6 with -v and runs to the end of the record.

As built in ff:

  • Item 4 in part. -kNr reverses one column. There is no -r for all: -r is a primary (V01).
  • Resolution. The comparison order is the named columns, then the columns not named, left to right, ascending. With a bare -k the name leads: 6, then 1 to 5. -k5,4 is 5,4,1,2,3,6.
  • Types. Columns 1, 2 and 4 compare as unsigned numbers and 5 as a signed number, by value at any width. Column 6 compares as bytes.
  • Null column. Column 3 is a dot in every record and compares equal.
  • Column 6 is the name as printed. On a -v line that is the path and its indicator, on a bare name the path alone. The two differ in order where a directory and a longer name share a prefix: a/ sorts after a b, a before it. Keyed so, ff -k ... -v is what srt and cksh make of the same lines, and ff -k without -v is the bytewise order of the names shown.
  • Stability. Walk order is the last comparison, so the unstable library sort cannot reorder equal records.
  • Scope. Records from -f, -v and the default print are held until the walk ends; what -x and -j commands write is not sorted.

The srt equivalent of any ff list: the list, then the remaining columns, x added to 1, 2, 4 and 5. The suite checks three such pairs when srt is present, and two against cksh -n0 -x0 when cksh is.

5 Output

The default print and -f write the path. -v writes the cksh line, inode links . size mdate name, numbers in lowercase hexadecimal at the least widths cksh uses (%8jx %2jx . %8jx %08jx), the name with an indicator in the manner of ls -F. It is byte for byte what cksh -n0 -x0 writes for the same name. A time before 1970 is written with a minus sign, -12cff780 for 1960-01-01 UTC, as cksh writes it and as srt -x reads it; r0.6 wrote the two's complement, ffffffffed300880, which sorted after every later time.

Every record ends in newline, or under -Z in NUL. To a terminal, and not under -Z, control bytes and invalid UTF-8 in a name are written as \ooo.

6 Hash

ff reads no file and computes no hash. Column 3 is kept, as a dot, so that the columns of ff and cksh agree: it is the column where cksh writes shake256-N of the content, N hexadecimal characters, shake256-6 by default. The name is written with a hyphen and never with a slash, which is read three ways (bits, bytes, hexadecimal characters); plan-cksh.md section 6 has the case. To add the hash to what ff finds, ff ... | cksh.

7 Exit status and diagnostics

A bitmask: 1 usage, 2 environment, 4 node, 8 exec, 16 loop, 32 node changed. 1 and 2 are fatal. Diagnostics are one line on standard error, >>> ff : what 'name'[: why] (tag) for errors and ^^^ for warnings; the tag names the message and is the same in the function.

8 Package files

  • ff.c --- the binary; the usage and the manual are compiled in, the manual as chunks under the C99 literal limit. --man writes the man page source from the same text.
  • ff.fn.bash --- one enclosing function ff: a pass over the words for --fn, --bin and -V, the hand-over, then the translator in a subshell. Its usage and manual blocks are copies of ./ff -h and ./ff --help; the suite fails if they drift.
  • makefile --- targets all ff man test install clean uninstall; PREFIX is /usr/local for root and $HOME otherwise.
  • test-ff.sh --- POSIX sh; section 9.
  • README.md --- a general introduction.
  • plan-ff.md --- this plan.

The manual follows the cksh model: body indented four blanks, a blank line after each heading, example groups as sub-headings indented two blanks with a blank line before each; sections NAME to REVISION with KEYS, BASH FUNCTION, ENVIRONMENT and SEE ALSO cksh(1), srt(1), find(1); no HISTORY and no COPYRIGHT. The copyright stays in every other file.

9 Verification

make test runs test-ff.sh beside ./ff. Every behavior case runs through the binary and then through the function, which is always given --fn; a parity pass compares the two byte for byte.

  2. Remaining columns: -k5 equals -k5,1,2,4,6.

10 Dependency posture

The binary needs C99 and libc, and nothing else at run time; the directory walker is owned rather than fts(3); on Linux, user and group names resolve through getent(1) at a fixed path. No setlocale() call is made. Static on Linux and NetBSD; on Darwin the ceiling is dynamic linkage against libSystem alone.

The function needs bash 4, the native find, stat(1) in the GNU or BSD form, and for -k a sort with -z and -s. --help uses mandoc or nroff when the host has one and a pager otherwise; none is required.

  • Function: one enclosing function with hand-over; the header moved out of the function body.
  • makefile: one compile and link step, man and uninstall targets.

Defects corrected, found in the review of r0.6 and of this revision:

  • A negative mdate printed as two's complement (section 5), so -v was not what cksh -n0 -x0 writes and missorted under srt -x.
  • Ties ran from the keyed column rightward only and never reached the columns on its left.
  • The function sorted with the locale of the caller. Its helpers set local LC_ALL=C, which a child process does not inherit unless the variable is already exported, so under a caller's LANG the names of -k and of the emulated -S collated by locale where the binary compares bytes. Each sort now runs as LC_ALL=C sort.
  • The function took the stat of -v and -k records without regard to -H: for a symlink named as a path operand it wrote the link's line where the binary writes the line of the file the link leads to. It now follows the link for an operand under -H, and under either option falls back to the link itself where it leads nowhere.
  • -Sk5, a group ending in -k, was an unknown option.

Context

ff is a short-switch find: NetBSD find(1) semantics where they matter, one letter per switch, predictable on Linux and Darwin. The cksh project sets the development model and solution profile, carried forward whole:

  • one C99 binary, no dependency beyond libc, -static on Linux/NetBSD, libSystem-only on Darwin (cksh makefile link recipe, reused verbatim);
  • one shell companion with byte-identical output and exit status, verified by a parity section in test.sh;
  • -h short usage, --help full manual compiled in as chunked literals, man page derived from --help at build time (cksh cksh.1 rule);
  • exit status as an accumulating bitmask; one diagnostic path (msg/die), chkerr/chkwrn format with a hex tag per message;
  • makefile restricted to the GNU make / bmake / Apple make intersection.

Finding that reshapes the shell companion: Lua

Stock Lua (5.1--5.4) has no readdir, no lstat, no fnmatch, and no POSIX regex; its patterns are not ERE, so -E cannot be honored in pure Lua. Every filesystem call would route through io.popen/os.execute, which invoke sh -c --- a quoting and injection surface, plus a fork per directory. With the "no lua modules" rule in force (shell skill), luaposix/lfs are excluded, and Lua is not installed on this host either. The intuition that Lua offers better filesystem access holds only with modules.

Recommended companion instead: ff.fn.bash as a translator. It parses the ff grammar, emits an argv array for the host's native find (never eval, never a string), and runs it with -print0 piped into a bash post-filter only where the native dialect lacks a primary. The walk, lstat and regex engine are then the kernel-adjacent native find, which is exactly what the Lua walker would have been emulating through popen. Dialect probe once per call: BSD (find -E accepted, NetBSD/Darwin) vs GNU (-regextype).

Decided r1: bash-translator. Lua dropped.

Walker: owned, not fts(3)

fts is the high-frequency choice (every BSD find uses it) --- visibility bias flagged. Against it here: musl ships no fts (static musl link fails), glibc fts lacked LFS safety before 2.34, and fts's FTS_NOCHDIR/chdir modes give no per-open race proof. nftw has no subtree prune in POSIX. Owned walker:

  • openat(parent, name, O_RDONLY|O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC) then fstat and compare st_dev/st_ino with the fstatat(...AT_SYMLINK_NOFOLLOW) taken while listing; mismatch = swapped under us, warn, skip (bit 32).
  • fdopendir + readdir; d_type as a hint only, DT_UNKNOWN (xfs, nfs, some fuse) falls back to fstatat. lstat skipped entirely when no predicate needs it and d_type suffices (speed parity with find).
  • fd budget: keep the dirfd chain open to a cap (64), beyond it reopen from the nearest held ancestor component-by-component with O_NOFOLLOW; paths built in a growable buffer, never PATH_MAX.
  • -L: ancestor dev/ino stack for cycle detection (bit 16); -H follows only command-line operands.
  • -D post-order, -S lexicographic (strcmp, bytewise, like LC_ALL=C).

-delete (r2): spelled in full rather than a single letter so a one-keystroke typo cannot destroy data. Implies -D post-order, as find does. Removal is unlinkat(dirfd, name, 0 | AT_REMOVEDIR) against the already-verified parent dirfd --- the same race closure as -x: no path is re-resolved. An operand ending in .., or the root directory by device and inode, is refused whole, not walked, bit 4 (r8; before, only the node was refused and its contents were still deleted); . is walked and kept, as find does; non-empty dir failure = bit 4, walk continues. The bash translator maps it to native -delete (both dialects have it) after refusing the same operands itself.

Excluded phase 1: -ok, -fprint, -printf (GNU only anyway), -flags, -fstype.

Security posture

  • exec: fork+execvp on an argv array, {} as whole-argument substitution only; + batches sized against sysconf(_SC_ARG_MAX) minus environ; execdir semantics (./name in the opened dirfd via fchdir in the child) closes the path-swap race that plain -exec has.
  • output (decided r1): raw bytes (as find) under -Z or when stdout is not a tty; on a tty escape control characters (C0, DEL, and C1 as bytes 0x80-0x9f only when not part of valid UTF-8) as \ooo to block terminal injection. Test: fixture name with ESC, compare tty (via script) vs pipe.
  • exec PATH guard: -x refuses to run when PATH holds an empty or relative element (as GNU does for -execdir), since the child's cwd is the walked directory and a planted ./ls would otherwise execute.
  • regex: compiled once; BRE back-references can go exponential in glibc --- documented, not guarded. Glob via fnmatch; FNM_CASEFOLD needs _GNU_SOURCE/_DARWIN_C_SOURCE/_NETBSD_SOURCE (all three supply it, musl too).
  • inputs: every numeric argument range-checked (num() pattern from cksh.c 527), unknown switch = status 1 before any walk.

Darwin variations to weigh

  • Birth time: st_birthtimespec (Darwin, NetBSD); Linux needs statx (glibc 2.28, musl 1.2.5) and some fs return none --- -b fails soft there.
  • Timespec names: st_mtim (Linux, NetBSD alias) vs st_mtimespec (Darwin); one accessor macro chosen by makefile uname case, cksh style.
  • Case-insensitive APFS default: -n foo misses Foo the filesystem itself would open; -I exists for this.
  • Unicode normalization: HFS+ stores NFD, APFS preserves input form; precomposed pattern vs decomposed name fails to match. Documented, not normalized (normalizing needs tables --- a candidate owned table later).
  • Firmlinks / sealed system volume: / and /System/Volumes/Data differ in st_dev; -X from / stops at the data volume.
  • SIP/TCC: EPERM on ~/Library/Mail etc. even as root --- bit 4, keep walking, one warning per subtree.
  • Dataless files (iCloud, SF_DATALESS): opening triggers download; ff never opens regular files (only -e on dirs, -x children).
  • BSD flags / xattrs / ACLs (UF_HIDDEN, com.apple.quarantine): not phase 1; candidate -f flag later.
  • Regex: Darwin REG_ENHANCED avoided for parity; plain POSIX only, REG_EXTENDED since r10.
  • Linking: no static libSystem; stated in README, as cksh does.
  • Native find for the bash companion: Darwin find is FreeBSD-derived (-E, -depth n, time units, -Bmin) while NetBSD lacks some of these; translator keys on feature probes, not uname.

Implementation record (r3, first build)

Where the build departs from or fills a gap in the plan above:

  • -f added as an explicit print primary. The plan left no print primary, so find's -prune -o -print idiom had no ff spelling. -z keeps find semantics (true).
  • Timespec access uses #ifdef __APPLE__ in ff.c, not a makefile branch.
  • Evaluation recurses over the expression tree. The plan said it would not, but the recursion depth is bounded by the expression, not the tree.
  • A directory closing a loop is skipped without being tested, as find does (fts FTS_DC).
  • A ;-form command that exits nonzero is only false. Bit 8 is set for exec failure and for nonzero + batches, as in find.
  • The descriptor window is min(64, RLIMIT_NOFILE/2 - 8).
  • The bash translator exits 2 where the native find cannot express a request (see README), and it collapses native failures to 4.
  • Options are accepted anywhere, not only before paths; they are global.

Requirement: -r is always ERE; -n and -p stay glob; -I makes all three case-insensitive (it already did: FNM_CASEFOLD, REG_ICASE, find -iname -ipath -iregex; the usage line now names them). Reverses r1, which kept find's BRE default with -E to choose ERE. Factors: one regex dialect is one thing to learn, and ERE is the dialect of grep -E, find -E and most current tools; a choice between dialects served compatibility with find, which ff's one-letter grammar does not keep elsewhere. ff.c compiles every -r with REG_EXTENDED; ff.fn.bash always gives BSD find -E and GNU find -regextype posix-extended and wraps the pattern .*(re).*, so the BRE path that stripped ^ and $ is gone, and back-references are refused (2, tag 6ab7ff40) on every -r, since the wrapping group renumbers them. -E fails loudly, as -0 did at r8: an unknown option (1, tag 6ab7ff01) before the expression, an unknown primary (6ab7ff03) inside it, -IE unknown whole. A silent no-op was declined: it would let a reader believe -E still chose something. No other switch reads regex, so -E reaches nothing else; the native -E that -V shows on BSD is find's. Factors weighed and accepted: a BRE pattern carried over changes meaning without an error (( ) { } + ? | operators, \( \) \{ literal), some become errors (a{, a leading *), and ERE leaves back-references, empty alternatives and escapes such as \d to the C library, so what compiles is less uniform across glibc, Darwin and NetBSD than under BRE; documented, not guarded. Requirement: the manual describes the current implementation; the rationale and the history of a decision live here. So --help gains a REGULAR EXPRESSIONS section (the ERE syntax, the escapes POSIX defines, . matching /, bracket rules, classes, a BRE difference table, glob contrasted, three examples) and its HISTORY lines stay one-line summaries. Escapes are documented as POSIX defines them, \ before . [ ( ) { * + ? | ^ $ \, with ] and } alone already literal; the test that used \} now uses a\{2}. Requirement: --help runs through $PAGER, more when unset or empty (POSIX man's default), when stdout is a terminal; -h is one screen and is not paged. Factors: PAGER is the user's configuration, commonly with arguments (less -R), which an argv split could not honor, so it runs by /bin/sh -c (popen in ff.c), as man(1) runs it; -x/-j words still never meet a shell. SIGPIPE is ignored in ff.c, so a pager quit early ends quietly with status 0. A pager that cannot run (126, 127) is warned of (^^^, tag 6ab7ff4e) and the manual written directly, so --help never shows nothing. Hygiene: LeakSanitizer reported one allocation, main's paths array, whenever bad() or die() exited from inside the parser with the pointer held only in a register: argc words, once per run, freed by exit, never proportional to the walk. It moves to file scope beside tok, so it stays reachable; make test under ASan, UBSan and LSan is now clean with leak detection on, where before 132 cases failed on the sanitizer's exit status. ff.fn.bash follows the shell standard for here-documents: __FF_USAGE__ and __FF_MANUAL__, quoted, read with IFS= read -r -d '' and printed with printf '%s', no <<- tabs; test.sh's wrapper uses __FFT_WRAPPER__, and a parity case checks each delimiter is quoted and occurs once as a line. The help blocks are copied from the binary's -h and --help; the makefile does not regenerate them, and README no longer says it does. Compatibility

Stated requirement (r10): the grammar is still settling toward a stable requirement set and build, and incompatible changes are accepted until then: -k to -mode (r9), -0 to -Z (r8), BRE to ERE and -E retired (r10). Once the stable release is declared, backward compatibility is maintained. The changes so far mostly fail loudly: -E and -0 before a path are usage errors (status 1), and an old -k mode argument is now read as a path that cannot be stat'ed (status 4). The BRE-to-ERE change is the one that can change meaning without any error, which is why the manual's REGULAR EXPRESSIONS section carries the BRE difference table.
