srt plan

srt: a sort for system operators. One interface on Linux, Darwin and NetBSD, delivered as C99 source (srt.c) and a bash function (srt.fn.bash).

This plan drives the package revisions. It was written before any code, as the instrument for verifying intent, and it remains the record. Items marked V (section 2) began as ambiguities with a proposed default; nothing downstream of an unconfirmed V item was built until it was confirmed. Decisions are recorded in section 12, the affected sections are revised in place, and section 13 holds the status of each revision as built.

1 Purpose and scope

srt replaces the three native sorts with one grammar whose ordinary case is the operator's ordinary case: column-ordered keys (-k5,3 reads "column 5, then column 3, then the rest"), stable by default, byte-deterministic across hosts, and safe on inputs larger than memory.

In scope: text records, column keys, the five ordering options, check mode, unique, shuffle, indentation-block sort, external spill.

Out of scope, by requirement: character-offset sub-keys (-k2.3), key ranges (-k2,4 as "fields 2 through 4"), and the obsolescent +pos -pos form.

Not a drop-in for sort(1). Several letters keep their name and change their meaning (section 4); a script written for native sort must not be pointed at srt unexamined.

2 Intent verification

Each item states the ambiguity, the readings, and the proposed default.

V01 Role of srt.fn.bash. DECIDED: (a) as proposed. Readings: (a) translator --- the same grammar executed through native sort and POSIX awk where the binary is absent, after the ff precedent; (b) thin wrapper that locates and calls the binary; (c) independent pure-bash implementation. Proposed: (a). Mechanism is decorate-sort-undecorate: awk emits the key columns in key order as a prefix, LC_ALL=C sort -s orders it, the prefix is cut. Consequences to accept: the function inherits native memory behavior; -b under reading V03(B) is binary-only (the function refuses it with a diagnostic rather than approximating); a function named srt shadows a binary named srt in the same shell, so the function either carries a distinct name or defers to the binary when one is on PATH. Proposed: defer to the binary when present.

As built at r0.4 (20261114): the awk pass does more than reorder columns. It encodes every key --- bytes, d, f, i, n, g, H, v with all three refinements --- into a string whose byte order is srt order, and the native sort is asked only to compare bytes, stably, field by field (sort -s -t ... -k N,N[r]). No native ordering option is used, so the function owes nothing to which sort a host has; -u and -c are done in awk for the same reason. Records are padded to the widest column count so that a missing column and an empty one are the same key, as in the binary. Since r0.4.1 the file defines one name: everything else is inside srt (see section 13). SRT_FN=1 keeps the function when a binary is on PATH. What the function declines is listed in --help, section BASH FUNCTION, which the binary and the function share.

V02 -c and -C polarity. DECIDED: POSIX convention --- -c checks and reports, -C checks silently.[^1][^3] This reverses the initial request (-c silent, -C verbose) and removes both letters from the changed-meaning table of section 4. The report's form is V14.

V03 -b, --respect-blanks. In every native, -b ignores leading blanks.[^1][^3] Here it means the reverse family. Readings: (A) leading blanks are significant bytes in comparison, nothing more; (B) outline sort --- a line owns the more-deeply-indented lines that follow it; siblings at each depth are sorted, each parent travels with its subtree, recursively; (C) each contiguous run of equally indented lines is sorted in place, runs never mix. DECIDED: (B), outline sort, with indent identity: an indent is the exact byte string of leading spaces and tabs. Spaces and tabs may be mixed freely, but they never correlate --- no tab expansion, no width; two indents are the same only when byte-identical. Blank lines attach to the preceding block.

Derived from that decision (confirmed 20261113):

  • Parentage: a line is the child of the nearest preceding line whose indent is a proper prefix of its own. A line with no such predecessor is top-level.
  • Sibling group: children of one parent that share a byte-identical indent. Only a group is sorted. Children of one parent with different indents (a tab-indented child and a space-indented child) form separate groups, and groups keep their input order.
  • Consequence: <TAB>x is not a child of <SP><SP>y, whatever an editor displays.

Settled while building r0.3 (20261114); each is the plan's reading of a point the decision left open, stated in --help and pinned by tests, and each can be amended:

  • "Nearest preceding" is read with block closure: a line closes every open block whose indent it does not extend, and a closed block is not reopened. In A, z, <TAB>C, D the line D is a child of A, not of z, because <TAB>C closed z. The literal reading would lift D above C without any sort having asked.
  • A group is all children of one parent with the same indent, whether or not other-indent siblings lie between them; groups are written in order of first appearance.
  • Blank lines (empty, or only blanks) are not sorted. Each stays directly below the line it follows and moves with it; leading blank lines stay first.
  • -u under -b removes an equal sibling only when it is a leaf with no blank line after it. A line carrying a block is always kept, so -u never discards lines it did not compare.
  • -c/-C under -b require every group to be in order and report the first out-of-order line by input position.
  • Several inputs form one outline, in operand order.

V04 -k grammar. DECIDED:

  • -k5,3 and -k5 -k3 are identical; keys accumulate left to right.
  • Per-key options are letters appended to a column: -k5n,3fr. Permitted letters: d f g H i n r v.
  • Letters on a column replace the global set for that column; they are never added to it. -n -k1r gives column 1 the set {r} alone, so it sorts as reversed text, and reversed numeric is -k1nr. This is the operator's original requirement and the rule of sort(1). Confirmed 20261114 after an additive alternative was put forward and declined; --help section GLOBAL AND KEY OPTIONS carries the explanation.
  • A column named twice is an error (it is almost always native-sort habit, -k2,2, and silently accepting it hides the difference).
  • Column 0 and non-numeric columns are errors.
  • A line with fewer columns than a key names has an empty key there; empty sorts before non-empty.
  • After the named columns, the remaining columns compare left to right in natural order under the global options. With six columns, -k5,3 orders by 5,3,1,2,4,6 (amended by V20: as written this now holds for -k5n,3; with column 5 as text, 5 and 6 are one key).

V05 -u scope. Because the remaining columns always participate, two lines are "equal" only when every column compares equal under the options in force. -u therefore removes whole-line duplicates (modulo -f, -d, -n equivalence), keeping the first by input order. The native ability "one line per distinct key column" is lost. DECIDED: -u removes whole-line duplicates only. No --unique-key is planned.

V06 Default column separation. Without -t: POSIX splits at the blank-to-non-blank transition and keeps leading blanks inside the field; awk splits on blank runs and drops them. DECIDED: awk rule (space and tab only). With -t char: every occurrence separates and empty columns exist. char is one byte; \t and \0 are accepted escapes; multi-byte separators are an error.

V07 -S and the memory control. -S here follows NetBSD ("don't use stable sort")[^1]; in the GNU and FreeBSD-derived sorts -S is the memory size.[^2][^3] That leaves the memory budget without a letter. DECIDED: automatic budget (section 7) with override by environment variable SRT_MEM and long option --mem size only. size is an integer N with an optional suffix: b bytes (the default), k kibibytes, m mebibytes, g gibibytes; powers of 1024. Under -S the binary may choose a faster unstable algorithm; output order among equal lines is then unspecified.

V08 -R interplay. -R is a uniform shuffle of the output records, not the native "random hash of keys" that groups equal keys.[^3] DECIDED: -R with any of -k -d -f -g -H -i -n -r -v -b -c -C is an error; -R -u removes byte-identical lines, then shuffles; -t is ignored. Entropy from /dev/urandom on all three platforms, one owned path.

V09 -v definition. Native version sort (-V) carries special cases for suffixes and ~.[^3] NetBSD has no version sort at all.[^1] DECIDED in base: an owned natural order --- maximal digit runs compare by numeric value at any length (leading zeros ignored, then shorter run first), all other bytes compare bytewise.

Proposed amendment, three owned refinements that repair every "wrong" row (DECIDED 20261113):

  1. Suffix rule: a trailing sequence of .-plus-letter-initial alphanumeric components (.tar.gz, .tgz, .rpm) is set aside; stems compare first, whole keys break the tie.

  2. Tilde rule: ~ sorts before everything, including end of key.

  3. IPv6 class: a key that parses whole as an IPv6 address, with optional /length, compares by its 128-bit value, then by length. All such keys sort after all other keys. IPv4 stays in the natural class, where it is already correct and where a four-part version number is indistinguishable from an address.

    Reversed at r0.4.2: "parses" was first implemented with the C library's inet_pton. The Darwin and Linux libraries do not agree on what is an address, so one input got two orders --- the very thing section 6 exists to prevent, and a dependency the build discipline would have refused had it been sized first. The parser is now owned, in srt.c and in the function's awk alike: groups of 1-4 hex digits; :: at most once, standing for at least one group; an optional final dotted quad of decimal octets with no leading zero; no zone id; /length of 1-3 digits, at most 128. Anything else is ordinary text in the natural class.

Shapes that still differ from native -V after the amendment, documented and left alone:

  • 1.0a v 1.0.1: srt puts 1.0.1 first (. before letters); native puts 1.0a first.
  • Leading zeros 1.005 1.05 1.5: srt orders by value then run length; native puts more zeros first. Decimal fractions are -n work in either tool.
  • Package-manager grammar (epochs 1:2.0, release fields) is not modeled; hex strings such as commit ids are not numbers.
  • Mixed case (RC1 v rc1) is bytewise unless -f.
  • IPv6: zone ids (%eth0) do not parse and fall to the natural class. Native -V has no IPv6 handling at all; observed on GNU sort 9.4 it orders ::10 before ::a and treats 0db8, DB8, db8 as different. Here srt is the more correct of the two.

V10 Locale posture. See section 6. DECIDED: locale environment is not consulted; order is bytewise.

V11 Eliminated options. Section 4 lists them. Proposed: every eliminated option is a usage error naming the option, with two exceptions accepted silently as no-ops because they already describe srt's behavior: -s (stable) and -m (multi-file input already sorts to one output). Alternative: reject those too, for a smaller grammar. DECIDED: as proposed (-s and -m accepted as no-ops, all other eliminated options are usage errors); -i is retained for POSIX compatibility and leaves the eliminated list.

V12 --help. DECIDED: the manual is compiled into the binary as text; srt.1 is generated from it by make man, so the two cannot disagree. --help with stdout a terminal pipes that text through $PAGER, else less, else more, else writes it directly; with stdout not a terminal it writes directly. It does not call man(1), so it works before make install. -h prints the one-screen usage. Alternative reading: --help execs man srt; rejected as proposed because it fails uninstalled.

V13 -n extent. DECIDED: optional leading blanks, optional -, digits, optional . and digits. No exponent, no thousands separator, no +. A key with no leading number compares as zero. Decimal point is always . (section 6).

V14 -c report format. Reopened by V02. The initial request had the verbose letter report every input on stdout; POSIX has -c write a diagnostic to stderr on disorder and nothing on stdout. DECIDED, to follow V02 through: -c writes to stderr one line per disordered input, srt: name:line: disorder, where line is the first record out of order and standard input is named -; sorted inputs produce nothing; stdout is never written in check mode. All inputs are checked (no stop at the first disorder), so the report is complete. Under -u, "sorted" means strictly ascending, so a duplicate is a disorder. Alternative, if the per-file stdout report was the point: keep ok<TAB>name / disorder<TAB>name<TAB>line on stdout under -c.

V16 Default spill directory. New. The first draft defaulted to $TMPDIR, then /tmp. On hosts where /tmp is memory-backed, spill there spends the memory the spill exists to save. The Darwin sort keeps its temporaries in /var/tmp. DECIDED: -T dir, else $TMPDIR, else /var/tmp.

V17 -g and human-numeric. New, from the operator's question. Both are small in the binary --- one parse routine and one comparator each, no new dependency.

  • -g, --general-numeric: the key is read by C strtod, so exponents, inf, nan and hex floats are accepted. srt never calls setlocale, so the decimal point is . on every host. Order: non-numbers, NaN, -inf, finite values, +inf. Cost: values are double, so integers above 2^53 lose exactness (use -n, which is exact at any length), and it is the slowest key type.
  • -H, --human-numeric: sign, digits, optional fraction, optional scale letter K M G T P E Z Y (either case). Order is by sign, then scale letter, then number. As in the natives, the scale is not multiplied out: 1023K sorts before 1M, and so does 2048K. Fit for du -h, df -h, ls -lh output, where units are normalized.
  • Letter choice: -g is free in srt and matches the natives. Native human-numeric is -h, which srt gives to usage. Proposed -H: same letter, upper case, and its only native claimant is an ignored legacy flag on NetBSD.[^1]
  • Type letters d g H n v are mutually exclusive on one key.
  • Function gap, surfaced at r0: NetBSD native sort has neither -g nor a human-numeric nor a version sort.[^1] Settled at r0.4, and not by the refusal last proposed: the function encodes these keys in awk on every platform (V01, as built), so there is no per-platform behavior to refuse. The one remnant is hexadecimal floats under -g, which awk cannot read; the function declines them, exit 2. DECIDED: both adopted.

V15 Install layout. DECIDED: PREFIX default /usr/local for root and $HOME for anyone else (amended in r0.6 by the operator; make install PREFIX=dir overrides); bin/srt, share/man/man1/srt.1, share/srt/srt.fn.bash. Confirm the function's destination against the profile's function-file search.

V18 Choosing the function or the binary by option. New, from the operator, 20261114: an option, in place of or beside the SRT_FN environment variable, to force or allow only one form. DECIDED 20261114 as proposed: --fn and --bin; SRT_FN removed. Built at r0.5.

Proposed:

  • --fn: the bash function only. Given to the function, it translates and never hands over. Given to the binary, it is an error, exit 2 --- the binary cannot be the function, and saying so is what "only" means.
  • --bin: the binary only. Given to the function, it hands over to the binary on PATH, and if there is none it is an error, exit 2, rather than a quiet fall back to translation. Given to the binary, it is accepted and does nothing.
  • Neither: as now. The function hands over when a binary is on PATH and translates otherwise.
  • Both: usage error.
  • Placement: anywhere among the options, like any other. The function must decide before it parses, so it makes one short pass over the arguments that knows which options take a value (-k -t -o -T, --output --tmp-dir --separator --mem) and stops at --; an argument such as -o --fn is then a file name, not the option.
  • Names: long only. --fn matches the file name srt.fn.bash; no short letter is spent.

Decided: the two names as proposed, and SRT_FN removed (reason given: yes --- an environment variable that silently changes which program runs is harder to see than an option on the command line; the suite uses --fn).

V19 Hexadecimal keys. New, from the operator, 20261114. Decided, built in r0.6.

The case: a listing whose fourth column is a size in hexadecimal, right-aligned, and whose fifth is a hexadecimal time, srt -k5,4. Expected: by time, then by size. Got, within one time: 187c 1c40a 28f5 a3d bdc df4d.

Cause, reproduced on the build host: srt did what V06 says. Columns are split on runs of blanks and the blanks are dropped, so column 4 is compared as the text a3d, 187c, 1c40a, and as text 1c40a sorts before 28f5 and a3d after both. The native sort gives the wanted order only by accident of layout: its field keeps the leading blanks, and right-alignment pads the shorter numbers so that text order and numeric order coincide. With -b the native sort gives the same order srt does. No srt ordering option reads these keys as numbers: -n and -g stop at the first letter, and -v treats letters as text.

Proposed: a hexadecimal numeric type.

  • -x, --hex-numeric, key letter x: compare as hexadecimal integers. Optional leading blanks, optional -, optional 0x or 0X, then hex digits in either case. Leading zeros do not count; comparison is exact at any length; a key with no hex digit is zero; what follows the digits is ignored. No fraction.
  • The case above becomes srt -k5x,4x, or srt -k5,4x while the times stay the same width.
  • One of the type letters, so exclusive with d g H n v on a key. x is unclaimed in all three native sorts.
  • Cost: one parse routine in srt.c beside -n, the same encoding as -n with sixteen digits instead of ten, and the same in the function's awk; cases in sections 3, 14 and 15 of the suite.
  • Caution for the manual: under -x a word spelled from a-f is a number (bead, face), so the letter belongs on the columns that hold hexadecimal, not given globally over mixed columns.

Considered and not proposed:

  • Length-then-text order (shorter key first, equal lengths as text). It would serve any right-aligned column in any base, but it reads 0a3d and a3d as different numbers and depends on letter case.
  • Keeping leading blanks inside columns, as the native sort does. It reverses V06, makes order depend on how the producer padded, and breaks as soon as a column is left-aligned.

Decided 20261114 and built in r0.6, as proposed. Refinement from the operator: the hash column of a listing stays text. Within one run its width is fixed, so text order is value order; across runs with different digest lengths, text order keeps like prefixes adjacent, which is what is wanted there. x is for the size and time columns.

V20 The last column. New, from the operator, 20261114. Decided, built in r0.6.

The driving use is sorting the columns of file listings, whose last column is a file name that may hold blanks. Columns are words in the awk sense ($1, $2 ...) throughout; widths and padding carry no meaning. Rule, in the operator's words: the last column runs to the end of the record, unless -D is used; then -k is tested exactly, and with no -k whole lines are tested.

As built:

  • The highest-numbered column named in -k is the last one.
  • Compared as text (no type letter, d, v): it runs to the end of the record, blanks included. -k5x,4x,6 sorts by hex time, hex size, then the whole name.
  • Compared as a number (n g H x): it is its word, and the rest of the record is one further column, compared last. -k5x,4x puts the name after every other column.
  • Under -D (V21), and when any key counts from the end (V22), every named column is exactly one word.
  • No part of a record is ever outside the comparison.

Consequence, accepted by the operator: the example this plan began with, -k5,3 on six columns giving 5,3,1,2,4,6, now holds as written only when column 5 is numeric (-k5n,3). With column 5 as text, columns 5 and 6 are one key, then 3,1,2,4. For six one-word columns the two orders differ only where records agree on column 5 and differ on 6. The suite pins both.

Also accepted: two records that differ only in the blanks inside the last text column are different records there (a b c and a b c under -k2); blank runs between earlier columns still do not count.

V21 Duplicates. New, from the operator, 20261114. Decided, built in r0.6. srt only.

-D, --duplicates: print every member of each group of two or more records that are equal on all the named columns; with no -k, equal as whole records. Output is in sorted order, so groups are adjacent. With -u, identical records collapse first, so a group must hold two distinct records to print. Refused with -c, -C, -R, -b.

The conflict with V20 (a hash column extended to the end of the record would never repeat) is resolved by the operator's rule: under -D the named columns are words and nothing more. The rest of the record still orders the output, last.

As built: a filter holding one record back at the final writer, in the in-memory path and in the last merge pass alike; spilled runs and intermediate passes are unfiltered, so a group split across runs is still found. In the function, the same filter in the awk stage that strips the keys.

Limit, stated in the manual: under -D a last column holding blanks is tested by its first word (My File and My Tune agree on My). For names, split on the separator that cannot be confused: V22.

V22 Key grammar: bare -k, columns from the end, reverse. New, from the operator, 20261114. Decided, built in r0.6.

  • Bare -k names no column: the whole record is the key, which is the default. The word after -k is a key list only when it reads as one (^-?N[letters](,-?N[letters])*$); any other word is left as an option or a file. A file named like a list is written ./5 or placed after --.
  • -k-N counts from the end: -k-1 is the last column. This is the simple resolution for duplicate base names in different paths: srt -t/ -D -k-1. When any key counts from the end, every word is a column and none is extended (the count from the end must not depend on V20). A line with no separator is one column, so -t/ -k-1 treats a bare name as its own base name.
  • Reverse has two spellings and no third: -kNr for that column, -r for every column without letters of its own (-rk5). -kr5 is retired; srt refuses it with a message naming -k5r.

Key grammar shared with the listing tools

Recorded here because srt's -k was settled first, as the model for the next revisions of the two tools whose output it sorts. Their own plans govern; this is what was agreed in this one.

  1. Columns are words in the awk sense, counted from 1; widths and padding are not significant, and blanks may be squeezed.
  2. Sorting is asked for with -k list, col[opts][,col[opts]]...: the named columns in the order given, then the remaining columns left to right. Ties follow srt's order.
  3. A bare -k names no column. In the listing tools that means sort by file name; in srt, by whole record.
  4. Reverse is -kNr for one column or -r for all. -krN is not accepted anywhere.
  5. The listing tools know their own column types, so -k5,4,6 there is srt -k5x,4x,6 on their output: time and size by hexadecimal value, the hash as text.
  6. The name is the last column and runs to the end of the record.
  7. Option letters given up to make room: the checksum tool selects columns with -n[0..5] in place of -0..-5; the find tool keeps -0 and -1 and requires -k for sorting.

Without -c or -C, all inputs are sorted together to one output. With either, each input is checked independently; the exit status is 1 if any input is out of order.

Global and per-key options: an ordering option outside -k applies to every key, named or implicit. Options attached to a column replace the whole global set for that column, so -r -k5n,3 sorts column 5 numerically ascending, and column 3 and the remainder reversed.

Mutual exclusions (usage error): more than one of -d -g -H -n -v -x on one key; -c or -C with -o; the -R set in V08; -D with -c, -C, -R or -b.

Exit status: 0 success or sorted; 1 disorder under -c/-C; 2 error.

5 Comparison semantics

Record: bytes up to newline (NUL under -Z). A final record without a terminator is accepted and written with one. Embedded NUL bytes are data, never terminators, outside -Z.

Comparison of two records proceeds key by key: named columns in order, then remaining columns left to right. Per key: select type (n, g, H, v, d, or bytes), apply i and f, compare, apply r. The first non-zero result decides. If every key is equal the records are equal: stable order (input order, files in operand order) decides, or nothing does under -S.

With no -k and no -t, the whole record is one key and comparison is a single memcmp --- the fast path the common invocation takes.

-b (V03): parentage by proper-prefix indent, sibling groups by byte-identical indent. Within a group the comparator above orders siblings by their own line, with the indent removed before column splitting; each sibling is emitted with its whole subtree directly after it, and the subtree's own groups are sorted by the same rules. Groups under one parent keep input order.

-o: output is opened only after all input is read, written to a temporary sibling in the destination directory, synced, given the original's mode, and renamed. A destination that exists as a non-regular node is written through, not renamed over.

6 Locale

Proposed posture: LC_* and LANG are not consulted. Order is by byte value, which for UTF-8 input is code point order.

  • -f folds ASCII a-z only.
  • -d keeps space, tab, ASCII alphanumerics, and every byte >= 0x80 (so UTF-8 letters survive as data).
  • -i keeps ASCII 0x20-0x7E and every byte >= 0x80; ASCII control bytes and DEL are skipped.
  • Blank is space and tab. Decimal point is ..

Why this rather than strcoll: collation tables differ between glibc, Darwin's libc and NetBSD's, so a locale-honoring sort gives one input three orders, and sort | comm, sort | join, and -c against a file sorted elsewhere all fail quietly. The GNU manual carries a standing warning on exactly this and recommends LC_ALL=C for the traditional byte order.[^3] srt makes the recommendation the behavior. It is also the precondition for memcmp keys and for radix (section 8), and it removes a host-variable library dependency.

The honest cost: no language-correct alphabetical order (accented letters sort after z, case-fold is ASCII). Prevalence note: locale collation is the documented default everywhere, which reflects the standard's history more than operator need; operator pipelines overwhelmingly force C. If language order is wanted, the door is a later --locale option that switches the byte comparator to strcoll and disables radix --- an opt-in, never the default.

7 Memory and spill

Aim: when the input fits, pay nothing for the safety; when it does not, finish anyway.

Fits (the typical case). Input is read into large contiguous chunks (a chunk list, not one reallocating buffer, so growth never copies). A record index is built: pointer, length, and an 8-byte big-endian key prefix so most comparisons resolve on an integer compare without touching the record. One in-memory stable merge sort over the index; output written from the index. No temporary file is created, no budget arithmetic beyond one comparison per chunk.

Budget. Default: half of physical memory (sysconf page count and page size), reduced to any lower RLIMIT_AS/RLIMIT_DATA; fallback 1 GiB when the query is unavailable. SRT_MEM or --mem overrides (N[bkmg], V07); --mem outranks SRT_MEM. The budget is the primary mechanism because allocation failure is not a dependable signal: on hosts that overcommit, malloc succeeds and the process is killed later. Values below 64k are raised to 64k.

Reversed at r0.2: the first draft said a failed allocation would trigger the spill path. As built, a failed allocation is a diagnosed exit 2 naming --mem. Recovering mid-structure from a failed malloc bought little once the budget was partitioned (below), since each part then has a ceiling and allocation failure means the budget itself was set above what the host allows.

_SC_PHYS_PAGES is hidden under strict POSIX on Darwin and NetBSD, so srt.c defines _DARWIN_C_SOURCE and _NETBSD_SOURCE for that one call and falls back to 1 GiB where the name is still absent. Whether the query succeeds on each platform is visible with SRT_STATS=1 and is to be confirmed there, not assumed.

Partition (r0.2). The budget is divided so each part has a fixed ceiling: record bytes in chunks, one half; the index, one third; the scratch half-index of the stable sort, one sixth. Reaching either the chunk ceiling or the index ceiling with at least one record held triggers a spill. The test is made after every record, not after every read. Found by measurement: with short records the index (24 bytes a record) outweighs the data, and a single test per read let one read overrun a small budget.

Encoded keys (r0.5). For a keyed sort the keys of each batch are encoded before it is sorted (section 8, and srt.c, "key encoding"). The encoded batch takes a quarter of the budget, and the chunk ceiling drops from a half to a quarter to pay for it, so runs are about half as long when keys are encoded. A batch whose encoded keys would pass their quarter is sorted by direct comparison instead. The merge of runs and -c always compare records directly: the widest column count, which the encoding pads to, is known for a batch but not across runs. SRT_STATS reports batches as encoded=N compared=N.

Does not fit. When a ceiling is reached: sort what is held, append it as a run to the spill file in -T dir (default per V16), release the chunks, continue reading. At end of input, k-way merge of the runs by a min-heap. Details:

  • Reversed at r0.2: one spill file holds all runs as (offset, length) extents, read with pread, instead of one file per run. The file comes from mkstemp with a literal srt. template and is unlinked immediately, so no signal or crash leaves residue and no cleanup handler is needed. Open descriptors stay at two regardless of run count, so RLIMIT_NOFILE no longer bounds anything.
  • Fan-in is bounded by memory instead: budget / 4096 - 1 runs can be buffered at once. More runs than that are merged in passes, groups of consecutive runs going to a second unlinked file, the two files swapping roles each pass. Disk need: about the input size, twice that when a pass is required.
  • Stability across runs: equal records resolve to the lower run number, which is input order; consecutive grouping preserves this across passes.
  • SRT_STATS=1 (added at r0.2, not in the first draft) writes srt: stats: budget=N runs=N passes=N to stderr. It exists so the multi-pass route can be tested and so an operator can see what a --mem setting did.
  • -u is applied within each run and again in the merge.
  • Every write, flush and close is checked; a full -T filesystem is a diagnosed exit 2, never truncated output.

Modes outside the spill path.

  • -c/-C: streaming, two records in memory, no budget concern.
  • -R: in memory, a Fisher-Yates shuffle. Over budget, each record carries a 64-bit random tag into its run and the tags are merged --- a uniform permutation by the same machinery (equal tags, about n^2 / 2^64 likely, fall back to input order).
  • -R -u (r0.2): the tag is a keyed hash of the record, the key drawn from /dev/urandom per invocation. Identical records get identical tags and meet, so the ordinary -u removes them; order is by tag, then bytes, so only identical records compare equal. One mechanism serves memory and spill.
  • -b over budget: exits 2 with a diagnostic naming --mem. Subtrees do not partition into independent runs, and an external outline sort is a separate design. Surfaced as a known gap, not hidden.
  • One record larger than the budget: held anyway; the budget governs when to spill, not a record size limit.

The bash function has no spill of its own; it relies on native sort's, and it stages a keyed copy of the input in the -T directory first.

8 --radixsort

Standing among the natives: the FreeBSD-derived sort offers --radixsort as a request that applies only when the key specification allows[^2]; NetBSD's implementation descends from the 4.4BSD sort and names radixsort(3) among its references[^1]; GNU has no such option.[^3]

What radix needs is keys that order correctly as raw bytes. The section 6 posture supplies that for plain keys at no cost. The other types need an encoding step that turns each key into a byte string whose memcmp order equals the comparator's order:

  • f: fold while encoding. d: drop excluded bytes.
  • r: complement every byte of that key's encoding.
  • n: sign byte, digit-count, digits; negatives complemented.
  • v: each digit run prefixed by its length; ~ mapped lowest; stem before suffix; IPv6 as a class byte plus 16 value bytes and length.
  • g: the IEEE bit pattern with the sign bit flipped, negatives complemented. H: sign, scale rank, then the n encoding.
  • key boundaries: a terminator byte lower than any data byte.

Once encoded keys exist, three things follow together: MSD radix becomes possible, the 8-byte prefix of section 7 becomes exact for every key type rather than for plain keys only, and the spill merge compares encoded bytes. The encoding, not the radix pass, is the structural investment.

Assessment:

  • Gain is real for many short records with low-entropy leading bytes (hostnames, paths, timestamps): O(n x key bytes) against O(n log n) comparisons that each re-scan a common prefix.
  • Gain is small or negative for few records, long distinct keys, or numeric keys of wide range; the prefix-cached merge sort already takes most of the available win there.
  • Stability: MSD radix with an auxiliary array is stable and fits the default; the in-place variant is not and belongs under -S.
  • Memory: encoded keys enlarge the index, pulling the spill threshold in.

Proposal: do not ship --radixsort before r0.5. Build the comparator so that the encoding can be introduced behind it without grammar change; add --radixsort in a later revision as an explicit request, measured against the merge sort on operator-shaped inputs before any thought of making it automatic. If the option is accepted at all it follows the FreeBSD wording: used when the specification allows, silently the default algorithm otherwise.

This recommendation is a design judgment, not a measurement; no benchmark has been run.

Implemented:

r0.5.1 (6af889a5, 20261114)

Delivered as one archive, srt-r0.5.1.tgz. The program is unchanged from r0.5; the manual gains four lines, and with it the revision.

The Darwin failure, one case, encoded equals compared: srt -S -u -k2n: not a defect in the encoding. -S permits any order among records that compare equal, and the binary then uses the C library's qsort. With -u one of several equal records is kept, and which one depends on where qsort left them. The two routes sort batches of different sizes, so on a host whose qsort is not stable they can keep different records, each a correct answer. The build host's qsort happens to be stable, which is why the case passed there and why it was written wrongly: it asserted bytes where only the set of keys is promised. The case now asserts that -S -u keeps exactly one record per key and that its output is strictly ordered, on both routes. --help states under -S that with -u any one of the equal records may be kept and that the choice can differ between hosts.

Worth keeping from this: three times now a Darwin run has caught an assumption that held only on the build host --- the address library, the calling shell's contents, the library sort. Each was a place where the build host's behavior stood in for a rule.

Delivered as one archive, srt-r0.6.tgz. Built: V19 (-x), V20 (the last column), V21 (-D), V22 (bare -k, -k-N, reverse spellings).

Program. One routine, layout, now decides what a record's named keys and remaining columns are, and the comparison (reccmp), the key encoder and the -D test all read its answer; before r0.6 each split the record for itself. The split takes a limit: the words up to the highest named column, then the residue as one column. Hex keys parse like -n with sixteen digits and no fraction, and encode as sign, digit count, digits. -D is a one-record hold at the final writer. The function's awk program carries the same layout, encoder and hold.
