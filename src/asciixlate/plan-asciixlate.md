Requirements and decision factors for `asciixlate`, a UTF-8 to ASCII
transliteration utility governed by a local rule file. `asciixlate --help`
documents the current implementation; this file records why it is so,
what the 2.1.0 review found, and what remains open for verification.

<!--contents 2 3 pre="## Contents" post="---"-->

## Requirements

1. Convert UTF-8 text to ASCII, replacing a `sed` wrapper around `iconv`.
2. `---` for an em dash; `??` for a character with no mapping.
3. Local adjustment through a rule file at `~/.asciixlate` (dash, soft
   hyphen, and any other character), without recompiling.
4. One standalone binary on Darwin (primary), Linux/RHEL and NetBSD, with
   the usage and the manual compiled in.
5. Never lose the operator's bytes: no truncation before the input is
   read, every write checked, a failed run leaves the original intact.
6. Not aimed at low-resource hosts: whole-file buffering is acceptable.
7. (2.1.0) When a rule deletes an emoji, the space that set it apart is
   deleted with it.
8. (2.1.0) When no file is named and standard input is not a terminal,
   filter it in blocks, with a block size option, so memory does not
   grow with the input and a selection can be piped from an editor.

## Decisions

### Owned table, no iconv

The transliteration table (1,456 entries: NFKD folding, glibc seeding,
hand curation) is generated by `mktable.py` and pinned in
`translit_table.h`. `iconv()` output varies with the host's gconv or
libiconv data, Darwin does not resolve it from libSystem without
`-liconv`, pkgsrc libiconv renames the symbols, and glibc `dlopen`s gconv
modules at run time, which defeats `-static`. Owning the table retires all
four. The checked-in header is the authority; `make table` exists to audit
a Unicode upgrade by diff, and is not part of a build.

### Linkage

| Platform | `make` produces |
|---|---|
| Linux (glibc or musl) | static, no shared object |
| NetBSD | static |
| Darwin | dynamic against libSystem only |

Darwin ships no static libSystem and does not support `-static`; libSystem
alone is the ceiling there, with nothing from pkgsrc needed at run time.

### Make dialect

The `makefile` is written for the intersection of GNU make, bmake, pmake
and Apple make: no `ifeq`, no `$(shell ...)`, no `?=`. The platform test
runs in the recipe shell. `PREFIX` defaults to `/usr/local` for root and
`$HOME` otherwise; an install path outside `[A-Za-z0-9._/+-]` is refused.

### One manual

`-h` is a one-screen usage; `--help` is the manual, paged through `$PAGER`
(default `more`) on a terminal. The man page is derived from `--help` by
the makefile, section headings included, so the two cannot disagree.

### Decline rather than guess

A file is refused, by name and reason, when it is not a regular file,
exceeds `--max-size`, or shows a NUL byte in its first 8192 bytes. Each
named input is read whole before any output is opened. A stream has none
of these properties; what it keeps of them is stated under Standard input.

### Deleted pictographs

A rule mapping an emoji to `""` removes a word-like glyph; the blank that
set it apart is then doubled, leading, or trailing. The rule adopted:

- the trigger is a *pictograph* deleted by an empty replacement:
  U+1F000..1FAFF, arrows, miscellaneous technical, geometric shapes,
  miscellaneous symbols, dingbats, supplemental arrows B, U+2B00..2BFF,
  and four CJK-block emoji. Letters, punctuation and the invisibles (soft
  hyphen, zero-width and bidi marks) never trigger it;
- when a blank or the start of a line precedes the deleted run, the one
  space after it is dropped; at end of line or file, the one space
  already written before it is dropped;
- a pictograph abutting a word on its left keeps the following space,
  the only separator there is (`Thanks<hands> everyone`);
- joiners, variation selectors and further pictographs deleted in the
  same run count as one deletion;
- a rule on U+0020 itself is left to act.

Decision factors: the class is drawn by code point range rather than by
"any empty replacement" because the soft hyphen, the reason the empty
replacement exists, must not join words. Exactly one space, not a run,
keeps the change predictable. The built-in table deletes nothing in the
class (24 entries fall in the ranges, none empty), so output without a
rule file is unchanged from 2.0.0.

Each finding was demonstrated against the built 2.0.0 binary before the

## Standard input

### Why 2.0.0 did not read it

No technical obstacle forbade it. The 2.0.0 rewrite answered a proof of
concept whose defects were losses of data, and it bought its guarantees
with properties that only a named regular file has: a type to refuse, a
size known before reading, content read whole before any output exists,
and a path to replace atomically. Its two principal modes, `-i` and
`--report ... >> ~/.asciixlate`, need names. This is a reading of the
source and its suite; the 2.0.0 record states the boundary, not the
reasoning.

### Decision (requirement 8)

With no operand and standard input not a terminal, `asciixlate` is a
block filter: read a block, convert what is complete, write, carry the
tail. `-b SIZE` sets the block (256 bytes to 1G, default 64K, one pipe
buffer). Each `read` is converted as it arrives rather than waiting for
a full block, so output follows a slow writer. Named files keep the
whole-file path and every refusal it supports.

### What crosses a block edge

Keeping a UTF-8 sequence whole is necessary and not sufficient. Three
things can straddle an edge, and each is carried:

| Straddler | Carry |
|---|---|
| a UTF-8 sequence | conversion stops at a lead byte with fewer bytes after it than the sequence needs; the tail (at most 3 bytes) moves to the front of the next block |
| a multi-code-point rule key | conversion stops at a byte that can begin such a rule with less than the longest key after it (at most 63 bytes) |
| the pictograph rule | its two flags persist between blocks; one trailing space is withheld from each write, because the rule may yet retract it; the last byte written is remembered so "after a blank" is still answerable |

The carry is under 64 bytes and the minimum block is 256, so every block
makes progress. With no multi-code-point rules loaded, only an unfinished
sequence is ever held.

The carry is bounded and exact, not line-based: a line longer than the
block needs no special case. The suite holds the stream to the file path
byte for byte at block sizes 256, 257, 263, 300, 1000, 4096 and 65536 and
under 5-byte reads, over a text that puts every straddler at every phase;
removing either the tail carry or the withheld space fails those cases.

### What a stream gives up

| Guarantee | Named file | Stream |
|---|---|---|
| type refusal | before reading | not applicable |
| `--max-size` | before reading | does not apply; memory is bounded by `-b` |
| NUL sniff | first 8192 bytes, before output | the bytes of the first read, before output |
| nothing written on refusal | yes | yes for the sniff; a later failure follows output |
| `--strict` status | before or after output | after output |
| `-i`, `-o` | yes | usage error |
| `--report`, `-n`, `-k`, `-m` | yes | yes |

### Not done

- `-` as an operand remains a file name. Making it standard input, alone
  or among files, is small if wanted.
- Named files are still read whole, up to `--max-size` (64M). Routing
  them through the block path would bound their memory as well, at the
  cost of the pre-output refusals and the unchanged-file test of R7.

## Optimizations

Measured on Linux x86-64, static, 60.8 MB ASCII, 34.8 MB mixed text,
4.5 MB CJK with 20,000 distinct unmapped code points; conversion times
are the best of seven runs:

| Case | 2.0.0 | 2.1.0 |
|---|---|---|
| ASCII conversion | 99 ms | 92 ms |
| mixed conversion | 93 ms | 107 ms |
| `--report`, 20,000 distinct | 4083 ms | 47 ms |
| startup (`-h`) | 2 ms | 2 ms |

Conversion runs near 500 MB/s, and the two columns differ by less than
repeated runs of one binary do on this host. Nothing in the conversion
path is worth trading clarity for. Done: R19 (report), R7
(no rewrite of unchanged files). Candidates, not done:

- multi-code-point rules are tried in sequence at each candidate byte;
  an index by first byte matters only for rule files with hundreds of
  such rules;
- the built-in table is hashed at each start (under 2 ms); a sorted
  static table with binary search would remove the step and the
  allocation, at no measurable gain;
- the stream path bounds memory for standard input: 2.0 GB filtered in
  3 s inside an 8 MB address-space limit, where the file path fails on
  35 MB. Block size barely matters to speed: 34.8 MB took 122 ms at 256
  bytes and 81 ms at 64K.

## Open for verification

1. **Pictograph class.** Is the range list the right boundary? Arrows and
   geometric shapes are included because emoji are drawn from them; the
   rule only acts on an empty replacement.
2. **Before punctuation.** `Great <rocket>!` yields `Great !`; the space
   before is dropped only at end of line. Dropping it before `.,;:!?)`
   is a one-line change but wrong for French spacing.
3. **Standard input**: should `-` name it, and should named files take
   the block path too? See Not done, above.
4. **Table content.** NFKD turns the spacing accents U+00A8, U+00AF,
   U+00B4, U+00B8 into a space; glibc seeding pads fractions (` 1/4 `)
   and the curated degree sign is ` deg`. Candidates for `CURATED`.
5. **Non-ASCII output.** `-k`, and a rule whose value is not ASCII, emit
   non-ASCII without notice. Warn, or leave as the operator's choice?
6. **Ownership.** A rewritten file is a new inode owned by the invoker;
   no `fchown` is attempted, and the parent directory is not synced.
7. **Exit status.** 1 covers usage, rule file, refusal and I/O failure.
   The ff convention of status bits would separate them.
8. **`--report`** lists unmapped code points only; invalid bytes are
   counted but not listed, and the summary line is suppressed.
9. **`-s` with `-i`** rewrites the file and then exits 2.
10. **`mktable.py`** is Python and needs a glibc `iconv(1)`, so the table
    cannot be regenerated on Darwin or NetBSD. It was not run for this
    revision; `translit_table.h` is unchanged (Unicode 15.0). Pinning the
    317 glibc-seeded entries inside the generator would remove the host
    dependency.

## Compatibility

Breaking changes are accepted until the requirement set is stable.
Changes in 2.1.0 that alter the result of an existing invocation:

- a deleted pictograph takes one space (requirement 7);
- ASCII-led multi-code-point rules now fire wherever they match (R2); a
  rule file holding such a rule, dormant under 2.0.0, changes output;
- a quoted value ends at its first unescaped quote; `"a" b"` was the
  value `a" b` and is now an error (R3);
- `-o` no longer forces mode 0644 (R13); `-i` no longer touches an
  unchanged file (R7) and no longer replaces a symlink (R6);
- `=` alone, surrogate keys, `-M -1` and overflowing sizes are errors;
- with no operand and standard input not a terminal, input is filtered
  where 2.0.0 exited 1 (`no input files`); a script that relied on that
  error now waits on, or consumes, its standard input;
- `--version` prints `asciixlate 2.1.0 rev 6af37686`;
- package: `Makefile` is now `makefile`, `run.sh` is `test.sh`,
  `make check` is `make test`; the build rationale moved from
  `README.md` to this file. Remove the old `Makefile` and `run.sh`.

## Verification record

Linux x86-64, glibc 2.39, GNU make, as root and as an unprivileged user:

- `make`, `make test`: 142 passed, 0 failed, 0 skipped;
- gcc and clang, `-std=c99 -Wall -Wextra -Wpedantic`, no warnings;
- the suite under gcc ASan, UBSan and LeakSanitizer: 0 reports;
- the 2.0.0 suite (`run.sh`) passes against the 2.1.0 binary, 50 of 51;
  the one failure is its `no stdin, no args` case, which requirement 8
  reverses;
- stream output equals file output on the 4.5 MB and 34.8 MB test texts;
  output arrives before end of input (2 s gap observed across a pause);
- the 2.1.0 suite cannot complete against the 2.0.0 binary: it stops at
  the fifo case (R10), as the finding predicts;
- `example.md` converts byte-identically to `example.ascii.md`.

Darwin, by the operator, rev 6af37686: `make clean && make all test`
builds without warnings, links without `-static`, derives the man page,
and reports 134 passed, 0 failed, 3 skipped. The skips cover 8 cases
that need `/dev/full` (7) or `/proc` (1); R8 and R9 are therefore
verified on Linux only.

`make table` on Darwin stops at the seeding step (`iconv: cannot
convert`): the host `iconv` is not glibc's and has no `ascii//TRANSLIT`
data for those code points. `mktable.py` exits before it opens
`translit_table.h`, so the header is untouched. The makefile now tests
for a glibc `iconv` first and says so, rather than failing inside the
generator.

Not verified: NetBSD and bmake.
