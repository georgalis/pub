asciixlate 2.0

UTF-8 to ASCII transliteration under a local rule file. Self-contained: no libiconv, no gconv modules, no runtime data. The transliteration table is generated once and compiled in, so the same input yields the same bytes on Darwin, Linux and NetBSD.

make            # GNU make, bmake, or Apple make --- all three work
make check
make install

asciixlate -h is the one-screen option summary; asciixlate --help is the full manual, and make install derives the man page from it so the two cannot disagree.

Why the 1.0 build failed on Darwin

ld: symbol(s) not found: _iconv, _iconv_open, _iconv_close

macOS does not put iconv in libSystem. cc foo.c never resolves it; the 1.0 header comment claiming otherwise was wrong. The immediate fix for 1.0 is cc -O2 -o asciixlate asciixlate.c -liconv. With pkgsrc on the path there is a second failure mode behind it: pkgsrc GNU libiconv's header renames the symbols to libiconv*, so whichever iconv.h the include path finds first decides which symbol set the object file asks for, and the -L in effect decides which library answers. That is a link-order lottery on a machine with both.

2.0 removes the dependency, so neither failure can recur.

Makefile portability

The 2.0.0 Makefile used ifeq and $(shell ...), which are GNU-make-only: bmake could not parse the file, and the echo it fed to /bin/sh carried unbalanced quotes and parentheses. Both are gone. There are now no conditionals and no $(shell ...) anywhere; the platform test happens in the recipe shell, where $$ escapes a shell variable identically for GNU make, bmake, pmake and Apple's make:

asciixlate: asciixlate.c translit_table.h
	@case `uname -s` in \
	  Darwin) ld= ;; \
	  *)      ld=-static ;; \
	esac; \
	$(CC) $(CFLAGS) -o $@ asciixlate.c $$ld

Nothing in the file is dialect-specific, so pkgsrc bmake on Darwin and gmake on RHEL read the same rules.

Static linking

Platformmake produces
Linux (glibc or musl)fully static, no .so
NetBSDfully static
Darwindynamic against /usr/lib/libSystem.B.dylib only

Apple does not ship a static libSystem and does not support -static; a fully static Mach-O executable is not achievable. Linking libSystem alone is the closest equivalent and needs no Homebrew or pkgsrc at run time.

Note also that glibc's static linking and iconv() are a bad pair: gconv modules are dlopened at run time, so a -static binary that calls iconv can fail on a host with different gconv data. Owning the table avoids that entirely.

The rule file

U+2014  ---             # em dash
U+00AD  ""              # soft hyphen: drop
U+00A0  " "             # no-break space: one plain space
\xC2\xA9  (c)           # by byte sequence
<paste>  ---            # or paste the character itself as the key

Keys accept U+XXXX, 0xXXXX, \xHH..., or literal UTF-8 pasted straight out of a vim buffer. Prefix with = to force a literal that would otherwise look like a code point. A literal key of more than one code point becomes a longest-match rule.

Values run to end of line; a whitespace-preceded # starts a comment. Wrap in double quotes for an exact value --- that is how a replacement holds spaces, a #, or nothing. A bare empty value is an error; write "" to delete a character.

Building a rule file from real text

asciixlate --report archive/*.md >> ~/.asciixlate

--report converts nothing to disk and prints an editable stub for every unmapped code point, most frequent first. --list dumps the whole active table in the same grammar.

Table provenance

translit_table.h is generated by mktable.py from three sources, in precedence order: Unicode NFKD folding (1065 entries), glibc ascii//TRANSLIT output captured at generation time (317), and a curated list in the generator (74). Regenerate with make table and diff to audit a Unicode upgrade.

See asciixlate --help for everything else.
